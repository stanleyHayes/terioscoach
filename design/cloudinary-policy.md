# Cloudinary Media Policy — Terios Platform

> Contract for the storage adapter (BE-11) and both frontend apps.
> Account credentials pending (user). This policy is implementable without them.

## Folder structure

```
terios/
  cms/            # public website imagery — blog covers, page media
    blog/
    pages/
    testimonials/
  clients/
    {clientId}/   # client documents — wellness plans, handouts (PRIVATE)
      documents/
      signed-forms/
```

- Public CMS assets: delivery via public URLs + `f_auto,q_auto` transforms.
- Client assets: **strictly private** — `type=authenticated`, delivery only via short-lived signed URLs generated by the API after ownership check. Never expose client asset public_ids to other clients; the API is the only path.

## Upload presets

| Preset | Use | Mode | Constraints |
|---|---|---|---|
| `terios_cms_images` | dashboard CMS image picker | signed upload from admin app | jpg/png/webp, ≤ 5MB, folder `terios/cms/*` |
| `terios_client_docs` | practitioner shares documents | signed upload from admin app | pdf/jpg/png, ≤ 10MB, folder `terios/clients/{clientId}/documents` |
| `terios_signed_forms` | completed/signed form PDFs | server-side upload from API | pdf, folder `terios/clients/{clientId}/signed-forms` |

## Flow

1. Admin app requests an upload signature: `POST /v1/uploads/sign {preset, folder?}` (practitioner-only; API signs with Cloudinary secret, 10-min expiry).
2. Browser uploads directly to Cloudinary with the signature (no proxy through the API).
3. API stores `{assetId, publicId, folder, ownerClientId?, uploadedBy, createdAt}` in `documents`.
4. Delivery of client docs: `GET /v1/documents/{id}/url` → 302 to a signed URL (TTL ≤ 1h), ownership enforced client-side-of-API (client sees own only; practitioner sees all).

## Housekeeping

- Deleting a client record cascades to Cloudinary assets via admin API (credentials in API env only).
- Raw uploads rejected: `resource_type: image` or `raw` (pdf) only, no video/audio in v1.
