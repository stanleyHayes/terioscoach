# Terios UI revamp — route coverage

**Direction:** a living practice journal. Deep eucalyptus creates the frame; mineral ivory holds the reading surfaces; clay marks action and warmth. Outfit carries body and interface copy, while Figtree carries titles and wordmarks. A continuous botanical care thread replaces the old stack-of-generic-cards feel.

## Coverage matrix

| Surface | Routes | Revamp treatment |
|---|---|---|
| Public shell | all marketing routes, 404 | Rebuilt navigation, footer, mobile menu, skip link, focus states, content rhythm and branded fallback |
| Home | `/` | Dark editorial hero, oversized type, asymmetric service journal, proof and testimonial pacing, strong closing field |
| Practice story | `/about` | Full-bleed chapter masthead and purpose-built clinical-botanical artwork |
| Services | `/services`, `/work-with-me` | Numbered editorial service ledger, clarified booking journey and enquiry surface |
| Reading | `/blog`, `/blog/[slug]` | Asymmetric journal index, feature treatment and dark article masthead |
| Help and contact | `/faq`, `/contact` | Search-led two-column FAQ and elevated enquiry form |
| Legal | `/privacy`, `/terms` | Branded, readable policy summaries with explicit pre-launch review notice |
| Client access | `/login`, `/register` | Split-screen care narrative with focused form plane and mobile-first alignment |
| Client shell | all `/portal/*` | Dark two-tier navigation, active pills, care-record chapter headers, connective thread and redesigned loading/empty/error states |
| Client workspaces | overview, booking, sessions, room, forms, documents, payments, reviews | Purposeful record surfaces and route-specific actions while retaining all existing workflows |
| Practice access | admin `/login` | Split-screen practitioner story and focused sign-in plane |
| Practice shell | all admin dashboard routes, admin 404 | Dark command rail, atmospheric shell, mobile top bar, layered page headers and unified tables/modals/inputs/states |
| Practice workspaces | overview, calendar, availability, clients, client detail, services, payments, content, forms, enquiries, reviews, reports, room | Route-specific headers plus shared editorial data surfaces without changing operational behavior |

## Shared interaction contract

- All buttons, inputs, textareas, cards, modals, tabs, tables, skeletons, empty states and errors inherit the new visual language.
- Focus remains visible; reduced-motion preferences are respected; touch targets and horizontal overflow are handled at narrow widths.
- Functional APIs, route names and business rules are intentionally unchanged.
